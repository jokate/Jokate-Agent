# 카태 스튜디오 운영 수첩

문제가 생겼을 때 보는 문서다. 증상 → 확인 → 해결 순서로 쓴다.
처음 쓰는 방법과 폰 페어링은 [GUIDE.md](GUIDE.md) 를 본다.
예시의 `<서버주소>`, `<토큰>` 은 자리표시다. 실제 값은 이 문서에 쓰지 않는다.

## 1. 서버가 안 뜰 때

### 증상
- 앱이나 브라우저가 `<서버주소>:8020` 에 닿지 않는다.

### 확인
1. 자동 시작이 켜져 있는가. Windows 시작 폴더(Startup)에 `Agent Katae Server.cmd` 가 있어야 한다.
   이 파일이 `uv run python -m relay_agent.supervise 8020` 을 띄운다. 감독 프로세스가 서버가 죽으면 다시 띄운다.
2. 감독 프로세스가 떠 있는가. 작업 관리자에서 최소화된 `Agent 카태 - 서버 (자동)` 창을 찾는다.
3. 포트 8020 을 누가 쓰는가. `netstat -ano | findstr :8020`
4. 로그 파일은 없다. 자동 시작은 최소화된 콘솔 창 `Agent 카태 - 서버 (자동)` 에 `[supervise]` 메시지와 서버 출력을 보여 준다.
   로그를 보려면 작업 표시줄에서 그 창을 열어 본다. 창을 닫으면 서버도 멈춘다.

### 해결
- 자동 시작 켜기·끄기: `uv run relay autostart on` / `uv run relay autostart off`
- 직접 실행: `uv run relay serve` (포트 지정: `--port`)
- **주의: 서버가 켜진 채 저장소 폴더에서 `uv run` 이나 `uv sync` 를 하면 `relay.exe` 가 잠겨 실패한다.**
  테스트·설치는 `UV_PROJECT_ENVIRONMENT` 에 다른 가상환경 경로를 지정해서 한다.
- 재시작: 이 PC 에서 `POST /admin/restart`.
  - 다른 기기에서 부르면 403 이다.
  - 도는 런이 있으면 409 로 거절한다. 캠페인은 먼저 멈춘 뒤 재시작한다.
  - `KATAE_SUPERVISED=1` (자동 시작으로 뜬 경우)이면 감독 프로세스가 다시 띄운다. 아니면 `start.bat` 을 띄운다.
- 재시작하면 시작 때 끊긴 런과 캠페인을 서버가 스스로 이어간다 (`recover_interrupted`, `campaigns.recover`).
- 재시작하면 남은 **연결 코드는 모두 무효**다 (메모리에만 있다). 새로 받는다.

## 2. 앱이 '다시 연결하는 중'일 때

### 증상
- 앱이 계속 '다시 연결하는 중'이다.

### 확인
1. PC·폰 둘 다 같은 Tailscale 계정으로 로그인되어 연결 중인가.
2. 서버가 떠 있는가. 1번 절을 본다.
3. `uv run relay remote status` 로 나온 주소가 앱에 저장된 주소와 같은가.
   원격 접속을 켜거나 끄면 서버를 재시작해야 적용된다.
4. 주소가 `127.0.0.1` 이면 원격이 꺼진 것이다. 폰은 쓸 수 없다.

### 해결
- 연결 뒤 `/studio/*` 가 401 이면 기기가 폐기됐거나 토큰이 무효다.
  앱에서 새 연결 코드(5분·1회용, `POST /studio/devices/pairing`)로 다시 페어링한다.
- 기기 토큰은 시간이 지나도 만료되지 않는다. 사용자가 폐기하거나 기기를 삭제할 때만 무효가 된다.
  시간 만료는 연결 코드(5분)에만 있다. 그러니 401 이 아니면 다시 페어링할 필요가 없다.
- 이름이 안 풀리면 Tailscale IP 를 직접 입력한다. 자세한 표는 GUIDE.md 의 '안 될 때'.

## 3. 에디터가 멈췄을 때

### 증상
- Unreal 에디터가 응답하지 않는다. 작업이 에디터를 기다리며 멈춘다.

### 확인
- 상태: `GET /studio/projects/{id}/editor`
- Unreal MCP 포트: 프로젝트마다 `mcp_port` 가 있다. 55558 부터 배정한다. (55557 은 MNYS 몫이다.)
- 런 도중에는 30초마다 에디터를 살피고, 3번 연속 답이 없으면 그 런을 끊는다.
- 에디터를 켠 뒤 답을 기다리는 시간은 설정 `studio_editor_wait` (기본 300초)다.

### 해결
- 정지 후 시작: `POST /studio/projects/{id}/editor/stop` → `POST /studio/projects/{id}/editor/start`
- 정지의 `force` 기본값은 true 다. 요청 본문은 생략해도 된다.
- 그래도 안 되면 에디터 프로세스를 직접 닫고 시작을 다시 부른다.
- 시작·정지는 이 문서에서 API 경로로 안내한다. 앱 화면 이름은 앱 소관이라 여기에 적지 않는다.

## 4. 푸시가 안 올 때

### 증상
- 일이 끝나거나 승인이 필요해도 폰에 알림이 없다.

### 확인 (순서대로)
1. 서버 설정 `studio_fcm_key` 가 FCM 키 파일 경로인가. 비어 있으면 푸시가 꺼진다.
   첫 푸시를 보낼 때 읽는다. 서비스 계정 키는 저장소 밖 사용자 폴더의 `%USERPROFILE%\.katae\fcm-service-account.json` 에 두는 것을 권장한다. **키 내용은 어디에도 쓰지 않는다.**
2. 앱 빌드에 `google-services.json` 이 들어 있는가. 앱 저장소의 `android/app/` 에 둔다 (CAMPAIGN.md 명세 기준, 앱 저장소에서 실제 위치는 확인 필요).
3. 폰의 알림 권한이 허용인가.
4. 폰의 배터리 최적화에서 앱이 제외인가.

### 해결
- 빠진 것을 채운다. 설정 파일을 바꾸면 서버를 재시작해야 적용된다 (README 의 Running it). 1번 절의 재시작을 한다.
  푸시 키 경로는 푸시를 보낼 때마다 읽고, 경로가 바뀌면 키 파일을 다시 읽는다.

## 5. PC 가 저절로 꺼졌을 때

### 증상
- 앱이 연결되지 않는다. PC 가 꺼져 있었거나 다시 켜진 흔적이 있다.

### 확인
- 부팅 시각: Windows 이벤트 뷰어, 또는 `systeminfo | findstr /i "부팅"`.
- `runs/history.sqlite` 의 마지막 기록 시각을 본다. 부팅 시각과 비교하면 꺼진 시점을 짐작할 수 있다.

### 해결
- PC 를 켜면 자동 시작이 서버를 띄운다. 꺼져 있으면 `uv run relay serve`.
- 서버가 뜨면 '서버 재시작' 오류로 끊긴 캠페인을 이어간다 (resume). 끊긴 런도 이어진다.
- 연결 코드는 무효가 됐으니 필요하면 새로 받는다.

## 6. 사용량 한도에 닿았을 때

### 증상
- 캠페인이 멈춘 듯 보인다.

### 확인
- 사용량 한도에 닿으면 캠페인이 한도가 풀리는 시각까지 기다린다. 시각은 AI 제공자가 알려 준 값을 쓴다.
- 설정 `studio_usage_warn_at` (기본 0.90)은 경고 기준이다.
  `studio_usage_hold` (기본 꺼짐)를 켜면 경고 기준에서 새 작업을 시작하지 않는다.

### 해결
- 사람이 할 일은 없다. 기다렸다가 자동으로 이어진다.
- 한도에 덜 닿게 하려면 모델 상한을 낮춘다.
  - 캠페인: 캠페인 정의의 `model_cap`, `effort_cap`.
  - 스튜디오 직원: 설정 `studio_model_cap` (`haiku`|`sonnet`|`opus`|`fable`), `studio_effort_cap`.
  - 둘이 겹치면 직원 상한이 우선이다.

## 확인하지 못한 것

둘 다 앱 저장소에서 확인해야 한다.

- `google-services.json` 을 앱 저장소의 `android/app/` 에 실제로 두는지
- 에디터 시작·정지 앱 화면의 이름
