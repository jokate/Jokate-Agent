# 카태 스튜디오 사용 가이드

PC 에서 릴레이 서버를 켜고, 폰 앱을 설치해 페어링하고, 하루를 보내는 법을 적는다.
이 가이드만 보고 새 폰을 연결할 수 있어야 한다.
계약과 내부 동작은 `ARCHITECTURE.md`, 작업 목록은 `CAMPAIGN.md` 에 있다.

글에 나오는 `<...>` 는 자기 값으로 바꿔 읽는다. 실제 주소·토큰은 이 문서에 적지 않는다.

## 1. 준비

### PC

1. 릴레이 서버를 실행한다: `uv run relay serve` (기본 주소 `http://127.0.0.1:8020`).
   - 포트를 바꾸려면 `--port <번호>`.
   - host 는 3번 `relay remote on` 이 정한 값을 읽는다. remote 를 켠 뒤에는 서버를 다시 시작해야 반영된다.
   - 이 창은 계속 열어 둔다. 자동 시작(2번)을 쓰면 직접 켜지 않아도 된다.
2. 로그온 때 서버가 자동으로 뜨게 한다.
   - `uv run relay autostart on` — 켜기. 죽거나 재시작하면 다시 띄운다.
   - `uv run relay autostart status` — 상태 보기.
   - `uv run relay autostart off` — 끄기.
   - 옵션: `--port 8020`(포트), `--no-start`(등록만 하고 지금 시작은 안 함).
3. 폰이 들어올 수 있게 연다. Tailscale 을 쓴다.
   - `uv run relay remote on --tailscale`
   - 한 번에 세 가지가 설정된다: 바깥 접속 허용, 접속 토큰 생성, Tailscale 대역만 허용.
   - **켠 뒤 서버를 다시 시작한다.** 안 하면 반영되지 않는다.
4. `uv run relay remote status` 로 주소와 토큰을 확인한다.
   - 토큰을 새로 만들려면 `uv run relay remote on --tailscale --new-token`.
   - 이 PC 에서만 쓰려면 `uv run relay remote off`.
5. PC 에 Tailscale 이 설치되어 로그인돼 있어야 한다.

### 폰

- PC 와 **같은 계정**으로 Tailscale 에 로그인한다.
- 연결이 켜져 있는지(VPN 표시) 확인한다.

## 2. 앱 설치

1. PC 의 앱 폴더에서 APK 를 폰으로 옮긴다. (직접 빌드한 APK 를 쓴다. 스토어 앱이 아니다.)
2. 폰 설정에서 **출처를 알 수 없는 앱 설치**를 허용한다. 파일을 연 앱(브라우저·파일 앱)에 허용을 준다.
3. 갤럭시에서 막히면:
   - 자동 차단(Auto Blocker)이 켜져 있으면 설치가 막힌다. 설치하는 동안 끈다.
   - Play 프로텍트가 "앱 검사" 경고를 띄우면 "설치"/"무시하고 설치"를 고른다.
   - 문구는 기종마다 다르다. 실제 화면은 폰에서 확인한다.
4. 이미 설치된 앱 위에 덮어 설치할 수 있는 것은 **같은 키로 서명한 APK** 뿐이다. 키가 다르면 지우고 다시 깐다. (지우면 페어링도 사라지니 다시 한다.)

### 앱 안 갱신

앱은 스스로 새 버전을 확인하고 받는다. PC 에서 할 일은 폴더에 파일을 두는 것뿐이다.

1. 폴더: `%USERPROFILE%\.katae\app` (설정 `studio_app_folder`).
2. 그 안에 APK 와 `latest.json` 을 둔다.

```json
{"version_name": "1.4.0", "build_number": 14, "notes": "바뀐 점 한 줄",
 "apks": {"arm64-v8a": "app-arm64-v8a-release.apk", "universal": "app-universal-release.apk"}}
```

3. 새 APK 를 올릴 때마다 **`build_number` 를 올린다.** 앱이 설치된 빌드 번호와 비교해 갱신 여부를 정한다.
4. 앱은 `GET /studio/app/latest` 로 확인하고 `GET /studio/app/files/{name}` 으로 받는다.
5. 서버는 폴더를 읽기만 한다. 만들거나 올리지 않는다. 폴더가 비어 있으면 "갱신 없음"이다.

## 3. 페어링

폰을 PC 에 묶는 단계다. 기기마다 한 번 한다.

1. PC 에서 대시보드를 연다. 토큰을 물으면 서버 토큰(`relay remote status` 에 나온 것)을 넣는다.
2. **📱 폰 연결** 버튼을 누른다. 창에 세 가지가 뜬다.
   - 서버 주소 — `http://<PC 의 Tailscale 주소 또는 MagicDNS 이름>:8020` 형식.
   - 페어링 코드 — 일회용.
   - 한 줄 JSON — 주소·코드를 한꺼번에 붙여넣는 용.
3. 주소가 `127.0.0.1`·`localhost` 로 나오면 폰이 못 쓴다. 창에 경고가 뜬다.
   PC 에서 `uv run relay remote on --tailscale` 을 하고, 서버를 다시 시작하고, 코드를 새로 받는다.
4. 폰 앱의 **컴퓨터 연결 화면**에서 주소와 코드를 입력한다. 또는 한 줄 JSON 을 붙여넣는다. (QR 은 아직 없다.)
5. 코드는 **5분** 유효하고 **한 번만** 쓴다. 서버를 재시작하면 남은 코드가 모두 무효가 된다.
6. 성공하면 앱이 기기 토큰(`sdt_` 로 시작)을 받아 저장한다. 이 토큰은 그때 한 번만 준다. PC 에도 남지 않는다(해시만 저장).
7. 실패(`pairing_invalid`)는 코드가 틀렸거나 만료됐거나 이미 썼다는 뜻이다. 새 코드를 받는다.

### 안 될 때

| 증상 | 확인 |
|---|---|
| 서버에 닿지 않는다 | 폰·PC 가 같은 Tailscale 계정인가. 서버가 떠 있는가. `relay remote on --tailscale` 후 재시작했는가 |
| 주소가 127.0.0.1 | 원격 접속이 꺼져 있다. 3번 절차 |
| 이름이 안 풀린다 | MagicDNS 가 꺼져 있을 수 있다. 주소를 Tailscale IP 로 직접 입력한다 |
| `pairing_invalid` | 새 코드를 받는다 |
| 연결 뒤 401 | 기기가 폐기됐다. 다시 페어링한다 |

### 기기 관리

- 연결된 기기 목록: `GET /studio/devices` (폐기한 기기는 안 나온다).
- 이름 바꾸기: `PATCH /studio/devices/{id}`.
- 폐기: `POST /studio/devices/{id}/revoke`. 다음 요청부터 401 이고 실시간 연결(WS)도 끊긴다.
- **기기 목록·폐기 화면은 아직 없다.** 지금은 API 로만 한다. 폰을 잃어버렸다면 바로 폐기한다.
- 이 경로들은 서버 토큰이 필요하다. 토큰 없이 받는 것은 `POST /studio/devices/pair` 하나다.

## 4. 하루 흐름

### 4.1 프로젝트

- **가져오기**: 이미 있는 폴더를 지정한다. 엔진·MCP·하네스 여부를 감지해 등록한다. 기존 파일은 덮어쓰지 않는다.
- **만들기**: 새 프로젝트를 만든다. 하네스가 자동으로 세팅된다.
- **하네스**: 규칙 파일(`CLAUDE.md`, `CLAUDE.local.md`)이 없으면 직원이 스킬을 거의 쓰지 않는다. 그래서 세팅한다.
  - 빠진 프로젝트는 `POST /studio/projects/{id}/harness` 로 다시 한다.
  - 서버 설정 `studio_harness_root` 에 하네스 저장소 경로가 있어야 한다. 없으면 거절된다.
  - 하네스가 안 된 프로젝트에는 프로그램 직원을 배치할 수 없다.

### 4.2 인사 면담과 채용

1. 인사 직원과 1:1 로 면담한다. 어떤 일을 맡길지 말한다.
2. 인사가 채용안을 **채용(hire) 결재**로 올린다.
3. 승인 / 반려 / 수정 요청 중에 정한다. 승인할 때 일부 값을 고쳐서 보낼 수 있다.
4. 일이 밀리면 시스템이 "채용 권장" 결재를 낸다. **면담 시작**이나 **넘기기**를 고른다.

### 4.3 대화

| 방 | 규칙 |
|---|---|
| 1:1 방 | 그 직원이 답한다. 왕복 한도 없다 |
| 단체방·파트방 | 멘션한 직원만 답한다. 멘션이 없으면 **빠른 판단**으로 답할 직원을 정한다. 직원끼리 왕복은 6번까지 |
| 작업방 | 직원끼리 왕복은 20번까지 (설정 `studio_max_exchanges`) |

- 빠른 판단: 가벼운 모델이 직원별로 "이 글에 답할지" 예/아니오를 본다. 아무도 아니면 "답할 직원이 없다"는 글이 남는다. 이때는 멘션하면 된다.
- 직원에게서 직원으로 넘길 때도 멘션을 쓴다. 판단에서 빠진 직원은 멘션해야 답한다.
- 왕복 한도에 닿으면 방이 멈추고 알림이 온다(방마다 한 번).
  - 내가 그 방에 글을 쓰면 새로 센다.
  - 글 없이 이어 가려면 `POST /studio/rooms/{id}/continue`.

### 4.4 작업 제안 → 진행

1. 직원이 **작업 제안(task_proposal)** 결재를 올린다. 제목·이유·완료 기준이 있다.
2. 승인하면 작업이 줄에 선다. 고쳐서 승인할 수도 있다. 반려하면 직원이 새로 올린다.
3. 동시에 도는 작업은 최대 3개다(설정 `studio_max_runs`). 나머지는 기다린다.
4. 진행 중에는 작업방에서 직원의 대화와 지금 하는 일이 보인다.
5. 새 기능(`feature`)은 코드를 바꾸기 전에 **구조 선택(structure_choice)** 결재가 먼저 온다. A/B/C 중 고른다.

### 4.5 검수

작업이 끝나면 **검수(final_review)** 결재가 온다. 근거가 한 화면에 모인다.

- 한 줄 요약, 변경 파일과 patch, 스크린샷, 담당 밖 변경, 묻지 않고 처리한 판단, 비용.
- 완료 기준마다 **검증됨(자동/수동)** 또는 **검증 안 됨** 표시가 붙는다. 안 된 것은 안 된 대로 보인다.
- 결정은 셋이다.
  - **통과** — 로컬 git 커밋을 한다. 푸시는 하지 않는다.
  - **재작업** — 코멘트가 같은 대화로 들어가 직원이 다시 한다. 코멘트는 필수.
  - **되돌리기** — 변경을 되돌린다.
- "묻지 않고 처리한 판단"은 "물어봤어야 함"/"괜찮음"으로 표시할 수 있다.

### 4.6 결재함

모든 결재는 한 곳에 모인다. 종류별 결정은 아래와 같다.

| 종류 | 결정 | 알림에서 바로 |
|---|---|---|
| 작업 제안 | 승인 / 반려(코멘트 필수) | 승인 가능 |
| 채용 | 승인 / 반려 / 수정 요청(코멘트 필수) | 승인 가능 |
| 설계 승인 | 승인 / 수정 요청(코멘트 필수) | 승인 가능 |
| 구조 선택 | 선택지 고르기 / 수정 요청 | 앱을 열어야 함 |
| 질문 | 답하기(코멘트 또는 선택지) | 앱을 열어야 함 |
| 사전 승인 | 승인 / 반려 / 수정 요청(코멘트 필수) | 승인 가능 |
| 예산 | 승인 / 반려 | 승인 가능 |
| 위험 명령 | 승인 / 반려 | 앱을 열어야 함 |
| 검수 | 통과 / 재작업 / 되돌리기 | 앱을 열어야 함 |
| 채용 권장 | 면담 시작 / 넘기기 | 앱을 열어야 함 |

- 알림에서 되는 것은 **코멘트 없는 승인**뿐이다. 그 밖의 결정은 앱을 열어서 한다.
- 결재가 아닌 알림도 온다: 배치 필요, 선행 작업 반려·거절, 작업 시작 실패, 단체방 왕복 한도, 일일 보고 등.
- 왕복 한도 알림은 방을 음소거해도 온다.

### 4.7 직원 고치기

직원 프로필에서 한다. 직원 폴더는 자체 git 으로 관리돼 고칠 때마다 자동 커밋된다.

- **지침 고치기**: 직원 폴더의 `PERSONA.md`(성격·역할), `GUIDE.md`(일하는 법)를 고친다. `PUT /studio/employees/{id}/files/{name}`. 읽은 뒤 파일이 바뀌었으면 거절되니 다시 읽고 고친다.
- **모델·설정**: 같은 방식으로 `employee.yaml` 을 고친다. 검사에 걸리면 저장되지 않는다. (`PATCH /studio/employees/{id}` 는 이름만 바꾼다.)
- **배치**: `POST /studio/employees/{id}/assign` 으로 프로젝트에 넣거나 뺀다(`project_id` 가 null 이면 어느 프로젝트에도 안 둔다).
- **휴직**: `POST /studio/employees/{id}/leave` 로 쉬게 하거나 복귀시킨다. 작업 중이면 거절된다.
- **퇴사**: `POST /studio/employees/{id}/retire`. 기록은 보관되고 1:1 방의 대화도 읽힌다. 작업 중이면 거절된다.
- **메모리**: `GET /studio/employees/{id}/memory` 로 본다. 항목마다 고치기(`PATCH`)와 지우기(`DELETE`)가 된다.
- **되돌리기**: `GET /studio/employees/{id}/history` 로 이력을 보고 `POST /studio/employees/{id}/revert` 로 옛 버전으로 돌린다.

### 4.8 채팅방 지우기

| 방 | 할 수 있는 것 |
|---|---|
| 단체방 | 보관(`POST /studio/rooms/{id}/archive`) 또는 삭제(`DELETE /studio/rooms/{id}`). 삭제하면 글·구성원·첨부가 지워진다 |
| 1:1 방 | 글만 비우기(`POST /studio/rooms/{id}/clear`). 방은 남고 대화는 처음부터 다시 시작한다 |
| 작업방·파트방 | 지울 수 없다 |

- 직원이 그 방에서 일하는 중이면 거절된다. 끝난 뒤에 한다.
- 지워도 결재·작업·직원 메모리는 남는다.

## 5. 안전장치

직원은 PC 에서 명령을 실행한다. 아래 보호가 항상 켜져 있다.

### 막는 것 (물어보지 않고 거부)

- 디스크 포맷·파티션
- 시스템 폴더·사용자 프로필 통째로 삭제
- 비밀 접근 — ssh 키, 브라우저 프로필, Claude 자격 증명, `%USERPROFILE%\.katae\`
- 보안 설정 변경 — 방화벽, Defender, 계정, 레지스트리(HKLM)
- 릴레이 서버 끄기·재설정 (`relay serve`·`remote`·`autostart` 포함)
- 보호된 폴더에 쓰기 (서버 코드, 실행 기록)
- 결제·송금 API 호출, 서비스 계정 만들기

### 물어보는 것 (위험 명령 결재로 올라옴)

- `git push`, `reset --hard`, `clean -f`
- 등록된 프로젝트 밖에서 삭제·이동
- 프로그램 설치·제거, 전역 환경 변수
- 종료·재시작·절전
- 1GB 넘는 내려받기, 처음 보는 호스트로 올리기

승인한 것은 그 결재 한 건이다. 허용 목록이 늘어나지 않으니 같은 명령을 다시 하면 다시 물을 수 있다.

### 사용량 안전망

- 직원별 모델·노력치를 낮추는 것이 사용량을 줄이는 기본 방법이다.
- 안전망은 폭주만 막는다.
  - 동시에 도는 작업 최대 3개 (`studio_max_runs`).
  - 직원 간 왕복 한도 (작업방 20, 단체방·파트방 6).
  - Claude 사용량이 90%(`studio_usage_warn_at`)에 가까우면 **알림만** 온다. 새 작업을 멈추려면 `studio_usage_hold` 를 켠다(기본 꺼짐).
  - 디스크 여유가 5GB(`studio_disk_min_free_gb`) 아래로 내려가면 알린다.
- 설정은 서버 설정 파일에서 바꾼다.

## 6. 확인하지 못한 것

- 앱 화면 이름(컴퓨터 연결 화면 등)은 대시보드 📱 폰 연결 창 안내문의 "컴퓨터 연결 화면"(`relay_agent/dashboard.html` 1522행)을 그대로 따랐다. 앱의 실제 화면 이름은 앱 저장소에서 확인한다.
- 갤럭시 자동 차단·Play 프로텍트의 실제 문구는 기종마다 다르다. 폰에서 확인한다.
- MagicDNS 를 끈 환경에서 이름이 풀리는지는 실제 폰으로만 볼 수 있다.
- 기기 폐기 화면과 QR 연결은 아직 없다.
